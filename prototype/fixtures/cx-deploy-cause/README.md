# CX-DEPLOY-CAUSE counterexample (`0.1.0-spike`)

Developer-authored regression fixture added for PR #13. It is **not** an independent or held-out case and is not part of the planned [corpus](../../../docs/scenarios/corpus-plan.md). Generated by [`build_counterexamples.py`](../../fixture_tools/build_counterexamples.py); ground truth is in `prototype/truth/` and only the scorer reads it.

- **Genuine cause:** Deployment `checkout-api` revision 2 (09:00:00Z) changes the image and adds env `DB_POOL_MAX=4`, which overrides the ConfigMap value 50 on new pods only. New pods log `CONFIG_LOADED value=4 source=env` and then `POOL_EXHAUSTED`; old pods never show the symptom.
- **Correlated non-cause:** ConfigMap `checkout-db-pool` changes `log.level` debug→info at 09:01:15Z, the change closest before the error-ratio onset (09:01:45Z). No mechanism maps `log.level` to pool exhaustion.
- **Expected:** the engine supports the rollout through its typed `field_changes` entry and new-revision consumption; the naive baseline picks the ConfigMap change.
