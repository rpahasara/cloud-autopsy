# Held-out fixture and ground-truth schema reference

Data contracts for authoring CA-SCENARIO-008, 009 and 010 against frozen candidate `c21b50dc5edd6cd07de55d2f3e0bce6103b4d952`. This page describes **input and answer formats only**. It deliberately says nothing about how the investigation engine decides; do not infer or seek its rules (see [author restrictions](README.md#author-restrictions)).

All JSON must be strict: UTF-8 without a byte-order mark, no duplicate keys, no floating-point numbers, NaN or Infinity. Carry decimals as strings (`"0.182"`). The kit's `freeze` command rejects anything else.

## Fixture directory

One directory per family, kept **outside any Git checkout**. No file or directory name may contain `truth`.

| Path | Required | Purpose |
|---|---|---|
| `observations.json` | Yes | Base evidence returned by every source query |
| `source-plan.json` | Yes | What the investigation is asked to collect and which workload is in scope |
| `variants/<ID>.json` | Yes, at least `A` | Overlay operations applied to the base evidence for each variant |
| `synthesis-stubs/<name>.json` | Only if a variant uses `stub` mode | Canned untrusted "model" response |
| `fixture-manifest.json` | Yes | Generated by `heldout_kit.py manifest`; do not hand-edit |
| `README.md` | Optional | Free text; not hashed by the engine manifest, but hashed by the kit freeze |

## `observations.json`

| Field | Type | Meaning |
|---|---|---|
| `schema_version` | string | Copy from the template |
| `fixture_id` | string | Lowercase identifier, for example `ca-scenario-008`; must equal the manifest and truth `fixture_id` |
| `fixture_version` | string | Author-chosen version, for example `1.0.0-heldout` |
| `clock_domains` | object | Clock declarations keyed by domain name |
| `acquisitions` | array | One entry per source query |

### Clock domain

| Field | Type | Meaning |
|---|---|---|
| `status` | `declared` or `unknown` | `unknown` means no trustworthy bound exists for this clock |
| `offset_ms` | integer | Declared offset of this clock from reference time (omit when `unknown`) |
| `offset_uncertainty_ms` | integer | Plus/minus bound on that offset (omit when `unknown`) |
| `precision_ms` | integer | Timestamp granularity, for example `1000` for whole seconds |
| `provenance` | string | Where the bound comes from; synthetic fixtures use `fixture-declared` |

### Acquisition

| Field | Type | Meaning |
|---|---|---|
| `query_id` | string | Must match a `source-plan.json` query |
| `source_id` | string | Source system, for example `k8s-api`, `loki`, `prometheus` |
| `window` | object | `start` / `end` as RFC 3339 UTC strings |
| `status` | string | One of `complete`, `empty`, `partial`, `truncated`, `failed`, `denied` |
| `reason` | string | Optional; why the query was not complete, for example `connector_timeout` |
| `observations` | array | Observation records (may be empty) |

### Observation record

| Field | Type | Meaning |
|---|---|---|
| `source_ref` | string | Unique human-readable reference to the source record, for example `k8s:configmap/<ns>/<name>@<resourceVersion>` or `loki:{namespace=<ns>,pod=<pod>}#<line>`. Truth refers to evidence only by `source_ref` |
| `observation_kind` | string | Record type; see the table below |
| `source_uid` | string | Stable identity of the underlying object (Kubernetes UID, series ID). Two objects with the same name but different lives must have different UIDs |
| `source_version` | string | Version of that object the record describes (resourceVersion, revision, line number, sample time) |
| `entity` | object | `kind`, `namespace`, `name` of the Kubernetes or service object |
| `times` | array | One or more `{type, raw, clock_domain}`; `type` is `event`, `completed`, `terminated` or `active_since`; `raw` is the timestamp text exactly as the source would emit it; `clock_domain` must be declared |
| `attributes` | object | Kind-specific payload |

Observation kinds and attribute keys used by the existing development fixtures:

| `observation_kind` | Attribute keys |
|---|---|
| `configmap_change` | `data_key`, `before_value`, `after_value`, `before_value_sha256`, `after_value_sha256`, `previous_resource_version`, `actor` |
| `deployment_rollout` | `revision`, `previous_revision`, `changed_fields`, `field_changes`, `image_before`, `image_after`, `config_refs_before`, `config_refs_after`, `old_replicaset`, `new_replicaset`, `actor` |
| `replicaset` | `owner_deployment`, `revision`, `image` |
| `pod` | `owner_replicaset`, `node`, `restart_count`, `configmap_volumes` (each `{configmap, mount_path, sub_path}`) |
| `log_line` | `pod`, `template`, `fields`, `message` |
| `metric_sample` | `series`, `labels`, `value` |
| `alert_firing` | `rule`, `rule_version`, `expr_series`, `threshold`, `for` |

Notes for authors:

- `field_changes` entries in a rollout are `{config_key, before_value, after_value}` objects describing a typed configuration change carried by the new revision.
- In `log_line`, `template` is the application's structured message name (or `null`), `fields` holds its structured values and `message` is the raw text. Raw text is untrusted data and may contain hostile content.
- You may use observation kinds or attribute keys not listed here when your scenario needs them. Record them faithfully; whether the frozen candidate interprets them is part of what the evaluation measures.

## `source-plan.json`

| Field | Meaning |
|---|---|
| `plan_id`, `plan_version` | Author-chosen identifiers |
| `namespace` | Primary namespace of the incident |
| `incident_window` | `start` / `end` RFC 3339 UTC |
| `expected_acquisitions` | Array of `{query_id, source_id, evidence_class, mandatory_for}`. `evidence_class` is one of `K8S-CONFIG`, `K8S-DEPLOY`, `K8S-POD`, `LOG`, `METRIC`, `ALERT`. `mandatory_for` lists the cause categories (mechanism labels, see truth below) whose evaluation needs this query |
| `symptom` | `alert_rule`, `error_ratio_series`, `error_ratio_threshold` (decimal string) |
| `candidate_scope.workload` | `{kind, namespace, name}` of the affected workload |
| `limits` | Copy from the template |

## `variants/<ID>.json`

| Field | Meaning |
|---|---|
| `variant` | Variant ID, for example `A` |
| `description` | Neutral description. **Must not state the expected answer**; the executor can read it |
| `synthesis` | `{"mode": "disabled"}` or `{"mode": "stub", "stub": "synthesis-stubs/<name>.json"}` |
| `ops` | Ordered overlay operations (empty for the base case) |

Overlay operations:

| `op` | Fields | Effect |
|---|---|---|
| `remove_observation` | `source_ref` | Drop that record |
| `add_observation` | `query_id`, `observation` | Append a full observation record to that query |
| `set_acquisition_status` | `query_id`, `status`, `reason` | Change a query's status |
| `set_clock_domain` | `domain`, `clock` | Replace a clock declaration |
| `set_time_raw` | `source_ref`, `time_type`, `raw` | Replace one timestamp's raw text (for example a malformed one) |

## Synthesis stub

`{"stub_version": "0.1", "behavior": "respond" | "timeout" | "unavailable", "response": <any JSON>}`. A `respond` stub stands in for an untrusted model output; it may be malformed or hostile on purpose. The response contract a well-formed reply would follow is `{contract_version, bundle_digest, claims[], limitations[]}` with claims `{claim_id, kind, text, evidence_ids[], assertion_keys[]}`.

## Ground truth (`ground-truth.json`)

Kept by the custodian **outside the repository** until scoring. The frozen scorer reads these fields; missing required fields make scoring fail, which is reported, never repaired after results are seen.

| Field | Required | Meaning |
|---|---|---|
| `truth_version`, `scenario_id`, `fixture_id`, `fixture_version` | Yes | Identity; `fixture_id` must match the fixtures |
| `custody_note` | Yes | Who wrote and holds it |
| `causal_change` | Yes | `null` when no change caused an incident, otherwise `{mechanism, entity, source_ref, failure_mechanism}` |
| `false_cause` | One of these two | A single declared misleading change `{mechanism, entity, source_ref}`, or `null` |
| `non_causes` | One of these two | A list of declared non-causal changes (use for benign cases or several distractors) |
| `required_evidence.base` | Yes | `source_ref`s a complete investigation must include |
| `required_evidence.withheld_by_variant` | Yes | Variant ID → `source_ref`s that variant removes (object, may be empty) |
| `variants.<ID>` | One per variant | Expected results; see below |

`mechanism` is a cause-category label. The development truth files use `config_value_change` (a ConfigMap data change) and `deployment_rollout` (a Deployment template revision). If the true cause is neither, write a descriptive label `other:<short-name>` and explain it in `failure_mechanism`; the case is still scored and reported, and it cannot be credited to any method that does not name it. `source_ref` must identify the **exact** change event; correctness is judged on it.

Per-variant expectations:

| Field | Required | Values |
|---|---|---|
| `expected_outcome` | Yes | `resolved` (a single cause should be named) or `abstained` (a careful investigator should decline) |
| `expected_cause` | Yes | `causal_change` when resolved, otherwise `null` |
| `expected_run_state` | Yes | `deterministic_complete`, or `partial` when any expected source is incomplete or a synthesis attempt is rejected or unavailable |
| `expected_synthesis_status` | Yes | `disabled`, `structurally_validated`, `rejected` or `unavailable` |
| `expected_gaps` | Yes | List of `{query_id, type}` with `type` in `missing`, `failed`, `truncated`, `unverifiable`; empty when all sources are complete |
| `false_cause_trap` | Yes | `true` when the variant contains a declared misleading change |
| `expected_abstention_reason` | No | Only `no_symptom_observed` is defined so far; omit otherwise |
| `expected_order` | No | List of `{a, b, order, why}` pairs of `source_ref`s with `order` `before`, `after` or `unordered`, judged from the declared clock bounds |
| `malicious_source_ref` | No | `source_ref` of hostile evidence that must never be used as support |
| `bundle_equivalent_to` | No | Another variant ID whose evidence bundle should be identical |
