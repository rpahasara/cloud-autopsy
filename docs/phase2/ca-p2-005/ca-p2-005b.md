## Step 1: R1 fixed first, in PR #37 (`e9fd738`)
- **What changed:** each collection now generates its own session identity once, `cs-<16 hex>` with 64 random bits, never derived from the user-supplied recording ID. The identity is recorded in the immutable recording, with the collector clock domain `ca-collector-<session_id>`.
- **Checks:** the converter refuses a recording whose collector domain is not its session's own, and replay reads the recorded identity. Rule profile 2 refuses an investigation whose `observed` brackets come from more than one clock domain (`observed_clock_domains_mixed`).
- **Tests:** two sessions with the same recording ID get separate domains and registries; mismatched or malformed identities are refused; replay is deterministic; generated identities are unique. CI run [43372926458](https://github.com/rpahasara/cloud-autopsy/actions/runs/43372926458) passed all four jobs.

## Does the new profile change conclusions?
**In the synthetic tests, yes, exactly where intended:**
- the positive control resolves under profile 2 and abstains under profile 1;
- the stepped-clock case (T4) resolves under profile 1 and abstains under profile 2.

Every other case concludes the same under both profiles.

**The positive control is not evidence that real collector investigations can resolve.** Its log source is placed on the collector's clock, which is a **synthetic assumption**. The real collector reads no logs, so collector-only investigations still abstain under both profiles. The recording test above and the PR #37 kind runs show this.
