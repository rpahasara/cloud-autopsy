## Evaluation-integrity hardening (before any new run)

The scorer (`ca-eval-scorer/0.2-provisional`) **refuses to score**, with exit status 2 and nothing scored, unless the records are exactly the pre-registered run set. It refuses:
- a missing (scenario, repetition);
- a duplicate;
- an unexpected scenario or an additional repetition;
- a record file name that disagrees with its internal IDs;
- a run attempted more than once, or pre-registered but never attempted, according to the append-only `attempts.log` the driver writes before each attempt.

Records are written with exclusive create, so a repeated attempt can never overwrite an earlier record. Every refusal has a regression test (`tests/eval`). No product rule changed.

## Timing sensitivity matrix 0.1

`tools/eval/timing-matrix-0.1.json` (`sha256:27e43de2…`) has 15 cells of 3 repetitions each (45 runs). Every cell is P1, N1, N2, N3 or N7 from 0.1, with a declared timing configuration and a **prediction written before running**.

**How the predictions were derived.** The rollout's observed bracket opens at the send time of the latest probe before the rollout. Probes are sent every *P* seconds, starting just after the session anchor. The action runs *A* seconds after the collector starts, which is roughly *A* − 1 s after the anchor.

**Scoring rules:**
- Positive cells are **measured against their predictions, with no pass threshold**.
- An abstention in a positive cell is recorded as an unnecessary abstention, not automatically an engine defect.
- Negative cells must all abstain, and a resolution there is a serious false-cause failure.
- Zero false causes, valid citations, zero leaks and byte-identical replay apply to every run.
- No cell is chosen, dropped or re-run after its results are seen, and no boundary is moved.

## How the runs are executed

Each run starts from a new branch whose commit is the frozen 007b baseline:
- `eval/ca-p2-007b-v02-run-1` runs scenario 0.2;
- `eval/ca-p2-007b-matrix-run-1` runs the matrix.

Their baselines are tagged `ca/eval-007b-v02-run1-baseline-<sha7>` and `ca/eval-007b-matrix-run1-baseline-<sha7>`. The two runs execute in separate GitHub-hosted jobs, which are separate virtual machines. Within each run, repetitions are sequential, each on its own fresh cluster. Every record carries its effective configuration and timing margins:
- the rollout bracket start relative to the window start;
- the smallest gap between the rollout bracket and a symptom bracket;
- the window decision.
