## What the collector establishes

**Coverage:**
- **Verified coverage** runs from the receipt of a consistent list's first page to the **send time** of a consistent-read probe whose resourceVersion the watch later reached. It is recorded on the collector's clock as a `watch_continuity` basis.
- **What never covers time:** receiving events or bookmarks, or keeping a connection open.
- **Disconnects:** a resume accepted from the last delivered resourceVersion keeps continuity. A 410, a refused resume, a relist, a denial, an invalid stream or a bound ends it, and the rest is a gap.

**Change times:** each change gets an `observed` bracket on the collector clock: after the send time of the latest consistent read with a lower resourceVersion, and no later than its receipt. It is encoded with the **unchanged** time contract (raw = lower bound, declared precision = width). `tests/contracts/test_observed_bracket.py` (identical to the plan PR's copy) proves this conservative.

**Clocks:**
- **The collector's clock:** declared `unknown` (no offset to any other clock), with continuity `declared_continuous`, or `step_declared` when a wall-clock step over 250 ms was detected.
- **API-server and component times** keep their raw values in a domain declared `unknown`.

**Never complete or empty when something is missing (F5.4):**
- `complete` means every change received in the proven range became evidence.
- `empty` means no change of any kind arrived.
- Withheld changes (Events about Secrets) and unconverted ones (pods or ReplicaSets without a controller in scope, Deployment changes with no new revision) make the segment `partial` / `changes_withheld`.

**Claims are checked against the evidence (F5.5):**
- The converter derives every basis from the recorded list, watch and probe entries. It refuses the whole recording when a stream is out of order, a resourceVersion regresses or is invalid, an object disagrees with its entry, a resume starts from another resourceVersion, or causality does not hold.
- `verify_bundle` re-derives the bundle and refuses any byte difference. The collector runs it on every run, and so does the CI job.

## <a id="findings"></a>Findings and deviations, reported faithfully

1. **The engine orders only by `event` timestamps** (`engine/timeline.py`).
   - Watch evidence keeps its server-clock `event` times (domain `unknown`), so the unchanged engine cannot use the `observed` brackets, and collector-only investigations keep abstaining, which is consistent with the safeguards.
   - Ordering by `observed` would be an engine change, outside this slice. **It needs separate approval**, so it was not made.
2. **`k8s_object_deleted` requires both `event` and `observed`** (the same collector bracket), not `observed` alone as the plan said. The engine relies on every kind having an `event` time. Without it, a deletion in a bundle would have crashed investigation. The kind is new, so no established meaning changed.
3. **The coverage basis is not shown in the frozen-input batch listing.** Adding it would have changed the frozen-input 0.2 record shape. The basis is covered by the batch digest, which the frozen input pins.
4. **Watch RBAC is a separate manifest** (`rbac-watch.yaml`), so the 004e job keeps proving that its collector cannot watch.
5. **Deployments segments are usually `partial` / `changes_withheld`.** Status-only Deployment changes have no evidence kind, so the rule in F5.4 applies to them. That is the honest result.
6. **Recording times are offsets from a wall-clock anchor.** The canonical JSON profile bounds integers to ±(2⁵³ − 1), so absolute nanoseconds are never written. The anchor is RFC 3339 text with nine fraction digits.

## <a id="limitations"></a>Remaining limitations
- Collector-only investigations abstain: there is no symptom source, limit values are withheld, and the engine orders by `event` times only (finding 1).
- The server chooses when to send bookmarks. Probes may be proven late, which shortens coverage at the end of a session; coverage is lost, never invented.
- An open watch outlives a revoked binding until its `timeoutSeconds` or the token's expiry.
- The self-built TLS client now also reads long-lived streams. It still needs an independent security review before any non-disposable cluster.
- Synthetic data only.
