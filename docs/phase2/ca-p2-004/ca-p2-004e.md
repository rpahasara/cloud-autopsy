# CA-P2-004e — read-only Kubernetes collector on a disposable kind cluster (implementation record)

**Scope:** the approved plan [ca-p2-004e-plan.md](ca-p2-004e-plan.md) (rev. 2, PR #32 at `919d3fd`; D1–D6 and §11 authorized by the product owner). Stacked on [004d](ca-p2-004d.md). Synthetic-only, under the [pre-gate development authorization](../ca-p2-003/ca-p2-003b-1.md).

**Boundaries kept:**
- the only cluster is created and deleted inside the `collector-kind` CI job;
- no access to any real, shared or existing cluster;
- no Secret or ConfigMap access; no watch, logs, exec, writes or cluster-wide permissions;
- no runtime dependency and nothing installed on the developer machine;
- no change to existing migrations, contracts, recordings 0.1/0.2, stored bytes or pinned digests;
- no API write routes and no dashboard change.

This is not a gate approval, a security review or a production-readiness claim.

## <a id="collector"></a>Collector (`src/cloud_autopsy/collector/`, `tools/collect_k8s.py`)

| Module | Responsibility |
|---|---|
| `client.py` | Verified-TLS HTTPS to a **loopback** API server only. Builds requests from a fixed allowlist of four namespaced GET list paths; `limit` and an opaque `continue` token are the only parameters. No proxies, redirects, kubeconfig or plugins. Errors are codes with an HTTP status, never bodies. Runs one list collection (below) |
| `project.py` | In-memory allowlist projection of every item; nothing else of a response is kept ([§sanitization](#sanitization)) |
| `collect.py` | Four collections, then the sanitized `ca-k8s-recording/0.3-provisional`, then the bundle (kinds 0.2, through the existing adapter), then a codes-and-counts report |

**One list collection (`collect_list`):**
- **One consistent collection:** every page must report the same **collection-level** `metadata.resourceVersion`. Otherwise `rv_changed`, and every page is discarded. Item resourceVersions play no part in this check.
- **Continue tokens are opaque:** printable, at most 8 KiB, URL-encoded as one value, used only within the same attempt, and never written or logged.
- **After `410 Gone`:** the attempt's token and pages, and any token in the 410 body, are discarded. The list restarts from the beginning, with no `continue` parameter, at most `max_restarts` times; if every attempt expires, the outcome is `expired`.
- **Bounds:** reaching `max_pages` while a continue token remains gives `truncated`. A duplicate uid gives `invalid`.
- **Recorded timing:** the client's wall-clock times for the attempt's first request and last response, and its monotonic elapsed time. **No API-server instant is claimed.**

## <a id="mapping"></a>Recording 0.3 and the fail-closed mapping (`app/k8s_recording.py`)

**The recording:** `ca-k8s-recording/0.3-provisional` has `provenance: "collector"` and an `unknown` API-server clock. It has **no `snapshot_at` and no `coverage` field**; a 0.3 recording containing either is refused. For each resource it records:
- the outcome code and HTTP status;
- an error code;
- the file and its SHA-256 (projected items only);
- the opaque `collection_resource_version`, the page and restart counts, and the remaining item count;
- the client timestamps.

On loading, the sanitized list must carry exactly the manifest's collection resourceVersion and no continue token.

**The mapping:**

| Collector outcome | Batch | Counted as covered? |
|---|---|---|
| `consistent` (including an empty list) | `partial` / `continuity_lost`, observations kept, unverified client-bracket coverage | No |
| `truncated` | `partial` / `page_limit`, truncated (omitted count from `remainingItemCount`) | No |
| `rv_changed` / `invalid` | `failed` / `invalid_response` | No |
| `expired` / `unavailable` | `failed` / `source_unavailable` | No |
| `denied` / `rate_limited` / `timeout` | `denied` / `authorization_denied`; `failed` / `rate_limited`; `failed` / `timeout` | No |

**How this shows up downstream:**
- **No coverage verified:** the collector never produces `complete` or `empty`. The frozen input shows `verified_ms == 0` and status `incomplete`, and **investigations abstain**.
- **Collection provenance:** for single-resource acquisitions the collection RV is kept in `cursor.after = "rv:<rv>"`. Deployments and ReplicaSets are separate collections, recorded with both RVs, and are never joined into one view.
- **ConfigMaps are never collected (D3).** Under the kinds 0.2 plan, `k8s.configmaps` appears as `failed` / `source_unavailable` ("not recorded").
- **Unchanged:** recordings 0.1 and 0.2 and their pinned outputs.

## <a id="sanitization"></a>Sanitization

| Kept (after type and length checks) | Never kept |
|---|---|
| Name, namespace, uid, resourceVersion, creationTimestamp, controller owner (kind, name, uid) | Annotations (except `deployment.kubernetes.io/revision`), labels, managedFields, `last-applied-configuration` |
| Pod: node, ConfigMap volume names and mount paths (`subPath` as a boolean), restart counts | env and envFrom values, Secret references and Secret or projected volumes (**counted only**), commands and args, Pod images, status messages |
| ReplicaSet/Deployment: the single container's name and image, ConfigMap reference names, the Progressing condition's type, reason and time | Condition messages, everything else in the template |
| Event: involved kind and name, type, reason, count, first and last time, reporting component | `message`, `note`, series details. **Events about a Secret are withheld and counted (D6)** |

## <a id="kind"></a>Disposable cluster and CI (`deploy/kind/`, `tests/kind/`, `collector-kind` job)

**Environment:** GitHub-hosted `ubuntu-24.04`. The job runs on manual dispatch and on pull requests that touch collector paths.

**Pinned tools and images** (inventoried, CI-only, Apache-2.0, license review pending):

| Component | Pin |
|---|---|
| `kind` v0.33.0 | SHA-256 `aee61515…de8d8e0d` (published checksum) |
| `kubectl` v1.37.0 | SHA-256 `6129359f…2c961a2f`. Test harness only; never the collector |
| `kindest/node:v1.37.0` | `@sha256:a1ed56cf…f580ae5` |
| `registry.k8s.io/pause:3.9` and `:3.10` | By digest |

**The cluster:** single node, API server on `127.0.0.1`.

**Synthetic workloads** contain planted values:
- a ConfigMap value and a Secret value;
- an env literal and a `secretKeyRef`;
- an annotation, and therefore `last-applied-configuration`;
- a rollout (pause 3.9 to 3.10);
- a container that cannot start, which produces Warning Events;
- a second namespace.

**RBAC:**
- **Identity:** a ServiceAccount without auto-mounted tokens.
- **Role:** in `ca-demo`, with `get`/`list` on pods, events, deployments and replicasets only.
- **Token:** a 10-minute TokenRequest token in a `0700` temporary directory, masked in logs.

**Negative RBAC, in two layers:**
1. **`kubectl auth can-i` as the collector:** the four permitted lists are "yes". Everything else is "no":
   - Secrets and ConfigMaps;
   - watch;
   - the `exec`, `log`, `portforward`, `proxy`, `scale`, `status` and `token` subresources, each checked with `--subresource`;
   - every write verb on the three workload resources;
   - another namespace, nodes and namespaces.
2. **Raw requests with the real token:** `tests/kind/kind_checks.py rbac` sends 22 forbidden requests through a test-only raw function that bypasses the allowlist. Every one must get **403**, and a permitted list must get 200, so a broken token cannot pass as "refused". The allowlisted client must also refuse to form those requests.

**Collection and checks:**
- **Collection run:** every collection is `consistent`. Pods, Deployments and Events are `partial` / `continuity_lost`, and ConfigMaps are not recorded.
- **Evidence:** the bundle contains `pod`, `replicaset`, `deployment_rollout` and `k8s_event` evidence.
- **Abstention:** offline investigation abstains, and so does **database-verified** creation on its own disposable PostgreSQL, which is stored once, verified on read and byte-identical to offline.
- **Leak scan:** finds no planted value, no Event text and not the token in anything written.

**Fault runs:**
- a page limit of 1 with a page bound of 1 gives `partial` / `page_limit`;
- a bad token gives `denied`;
- a closed port gives `unavailable`;
- deleting the RoleBinding gives `denied`.

**Cleanup:** the cluster and the credentials are always deleted, and the job checks that no cluster container is left.

## <a id="tests"></a>Offline tests (`tests/collector/`, the offline CI job and every OS)

A fake API serves synthetic lists with planted values, in-process and behind **real loopback TLS**. The throwaway certificate is generated by `openssl` at test time and never committed; CI requires it. The tests cover:
- **The allowlist:** other resources, namespaces, limits and paths are refused; only HTTPS on loopback is accepted.
- **Tokens:** opaque and encoded as a single value, refused when unsafe, never persisted.
- **Collection consistency:**
  - consistent pagination;
  - item RV drift does not matter;
  - a collection RV change discards everything;
  - a 410 restarts with no token reuse;
  - repeated 410s become `expired`;
  - the page bound truncates.
- **Failure mapping:** 401, 403, 404, 429, 5xx, 302, timeout, unavailable, strict JSON, wrong kind, missing RV, oversize pages and duplicates.
- **Sanitization:** no planted value survives projection, and Secret references are counted.
- **Fail-closed runs:**
  - batches are `partial`, never `complete` or `empty`;
  - `verified_ms` is 0 and the investigation **abstains**, never resolves;
  - an empty list is `partial`;
  - kinds stay separate;
  - faults become gaps.
- **Leakage:** nothing sensitive in written files, logs, stdout, stderr or exceptions; no token written.
- **Determinism:** replay is byte-identical, and the same API and clock give the same bytes.
- **Recording 0.3 refusals:** `snapshot_at` or `coverage`; wrong provenance or a declared clock; a mismatched RV; a failed collection carrying a file.
- **TLS:** collection over verified TLS; an untrusted certificate is refused before any request; redirects are not followed; a wrong token is denied.

## <a id="findings"></a>Defects and security findings during implementation

- **Test-harness defect.** `kubectl auth can-i get pods/log` answered "yes". kubectl reads `pods/log` as TYPE/NAME, a pod *named* `log`, which `get pods` allows. The check was wrong, not the Role; the matrix now uses `--subresource`. The raw-request matrix probes the real subresource paths.
- **Isolation rule extended.** The product-source isolation test lists packages allowed to do file I/O. The collector reads its CA and token files and writes outputs, so it was added, as `app`, `db` and `api` were before it.
- **RBAC limit.** The Role cannot stop the API server returning Pod env values to a permitted `list`. Protection relies on the in-memory projection, tested with planted values in the fake API and in the real cluster.

## <a id="limitations"></a>Remaining limitations

- **Always abstains.** No collection timing or continuous coverage can be expressed under the current batch contract (plan §6.5).
- **No ConfigMap metadata (D3).** The API-server clock is `unknown` (D4), so cross-source ordering cannot be established.
- **Self-built TLS client.** It needs independent security review before any non-disposable cluster.
- **Hosted runners.** `kind` occasionally fails to start; the job retries cluster creation once. The existing headless-Chrome startup flake in the dashboard browser tests also recurs (unrelated to this slice).
- **Synthetic only.** No real cluster, customer evidence or production use.
